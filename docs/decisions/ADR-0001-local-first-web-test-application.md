# ADR-0001：以本地优先 Web 测试应用取代微信小程序与 CloudBase

- 状态：已接受
- 决策日期：2026-08-26
- 决策人：项目负责人
- 适用分支：`feat/v1.0`
- 详细设计：`docs/superpowers/specs/2026-08-26-local-first-web-test-app-design.md`

## 背景

当前仓库已经完成阶段一至六的确定性计算、版本化规划、一周餐单、食材候选确认和受限助手能力，但客户端与运行时建立在微信原生小程序、CloudBase 云函数、文档数据库、私有存储和 CloudBase AI+ 之上。阶段七原计划把这些能力部署到受控 CloudBase 环境；真实私有输入、云端配置、供应商和外部审批尚未到位，当前没有需要迁移的正式用户数据。

项目负责人决定完全放弃微信小程序与 CloudBase 方向，把本仓库重构为最多五名测试人员使用的内部 Web 测试应用。测试人员从空本地数据库开始，只使用虚拟身体数据和明确标记的测试营养数据，不把结果用于真实饮食安排。生产应用另行开发，不属于本仓库当前交付范围。

## 决策

采用本地优先、无业务后端的响应式 Web 架构：

```text
React + Vite Web UI
  -> Web controllers/composition
    -> existing application services
      -> domain and deterministic calculation
      -> Dexie / IndexedDB repository
      -> browser OpenAI-compatible LLM provider
```

具体决策如下：

1. 新增 `apps/web`，使用 React、Vite、TypeScript、React Router 和 Dexie。
2. 保留并浏览器化 `packages/domain`、`packages/calculation`、`packages/application`、`packages/agent`、`packages/contracts` 及有用的供应商无关 Provider。
3. 保留现有 LangGraph 单 Agent、三项白名单命令、严格模型 schema、原文证据校验和最多一次修复；在助手路由按需加载。
4. 用 IndexedDB 保存单个本地用户的版本化聚合，不提供登录、账号、多端同步、云端备份或 CloudBase 数据迁移。
5. 构建时附带严格 `test_fixture` 数据集。测试人员必须确认只使用虚拟输入；所有规划和结果持续显示内部测试与非真实饮食提示。
6. 测试应用直接从浏览器调用固定 OpenAI-compatible LLM 地址。测试 Base URL、API Key 和模型由未跟踪的 `.env.test.local` 注入未跟踪测试制品，不由测试人员配置。
7. 接受测试 Key 会出现在浏览器制品并可能被提取的风险，只允许使用独立、低额度、短有效期、可撤销的测试 Key。真实 Key 不得进入源码、Git、日志、备份、导出、source map 或测试证据。
8. 原始食材图片只在当前页面内存中处理并直接发送到固定多模态模型；不持久化原图。候选必须映射到测试数据集，且用户确认名称和克数后才写入库存。
9. 静态站点托管、访问控制和生产发布不属于本决策范围。本仓库只交付可构建测试制品、本地预览、预检和验收清单。
10. Web 功能对等和替代测试通过后，删除 `miniprogram/`、`cloudfunctions/`、CloudBase 适配器、配置、构建脚本和部署文档。删除前保留旧平台作为只读对照，不进行双平台功能开发。

## 保持不变的产品约束

- 只支持健康成年人，并保留 `calculation-policy-v2` 的年龄、BMI、健康确认和必需输入门禁。
- 热量、营养素、食材克数和训练消耗只由确定性代码产生。
- 过敏原和忌口是硬约束；营养约束无解时明确失败。
- 过去事实不可改写，训练变更只影响正确的未来日期。
- 锁定或手动修改餐单不得被静默覆盖。
- LLM 只做意图识别、参数提取、受控解释和候选识别，不得成为数值来源。
- 模型输出继续经过运行时 schema 和领域命令校验。

## 本地数据与秘密边界

- IndexedDB 每个 origin 只保存一个本地用户聚合、应用设置和一份已校验测试数据集。
- 聚合继续保留 3,000,000 UTF-8 字节应用预算、版本、幂等记录和事务 revision。
- `PlanningRepository.read/transact` 继续是应用层与持久化层的边界。
- 提供白名单个人数据导出，以及独立的 `fitness-local-backup-v1` 完整备份/原子恢复；两者都排除测试 API Key。
- 删除本地账户时删除 IndexedDB、页面草稿和助手恢复状态，不执行云端清理。
- 测试 Key 只通过 `VITE_TEST_LLM_API_KEY` 注入内部测试构建；`VITE_TEST_LLM_BASE_URL` 和 `VITE_TEST_LLM_MODEL` 同样固定在构建期。

## 替代方案

### 继续 CloudBase 小程序

优点是能够复用现有部署工具和微信身份；缺点是仍需付费或升级云存储与 AI 能力，并继续受真实云端、账号、规则、供应商和审批阻塞。与项目负责人“完全摒弃之前小程序开发”的决定冲突，因此拒绝。

### 全部业务逻辑从零重写

优点是目录表面更干净；缺点是会放弃阶段一至六积累的确定性规则、版本语义和近千项测试证据，显著增加数值和安全回归风险，因此拒绝。

### 零后端并由每名测试人员自带 API Key

可以避免测试 Key 出现在统一制品中，但增加测试人员配置负担。项目负责人要求测试人员不提供 API Key，因此拒绝。

### 静态网页加无状态 LLM 代理

能够保护供应商 API Key，是面向生产或扩大测试范围时更安全的方案；但当前明确要求测试应用无后端，且接受短期测试 Key 暴露风险，因此本阶段不采用。

## 后果

正面后果：

- 不再依赖 CloudBase 数据库、存储、函数、AI+、微信身份或开发者工具。
- 结构化核心流程可以在浏览器本地运行，部署只需要静态文件。
- 已验证的业务核心和测试可以继续复用。
- 取消真实 CloudBase 数据迁移、双微信身份和云端备份恢复工作。

负面后果：

- 数据只存在当前浏览器 origin；清理站点数据、更换域名或设备会丢失，必须依赖本地备份。
- 不提供登录、多用户隔离、多端同步、远程恢复或后台管理。
- 测试 Key 位于浏览器制品并应视为可公开提取，额度损失只能通过独立 Key、低限额、短有效期和及时撤销控制。
- 浏览器直连依赖目标 LLM 服务正确支持 HTTPS 和 CORS。
- 内置营养数据只允许虚拟流程测试，不能把本仓库标记为生产就绪或用于真实饮食安排。

## 迁移与删除策略

1. 不迁移任何 CloudBase 数据；所有 Web 测试人员从空本地数据库开始。
2. 先完成 ADR、规格、实施计划和 Web 基础设施。
3. 逐阶段替换持久化、结构化规划、餐单、助手、图片和数据权利页面。
4. 每个阶段以替代自动化测试和浏览器验收为退出条件。
5. 只有功能对等门禁通过后才删除旧平台目录和依赖；Git 历史保留审计和临时恢复能力。
6. 最终清理后不得继续维护小程序或 CloudBase 双运行路径。

## 回滚

- 在旧平台删除阶段之前，任一 Web 阶段失败都可以回退该阶段提交；旧平台只作为代码对照，不恢复 CloudBase 发布计划。
- 旧平台删除后如需审计，可从 Git 历史查看；不得无设计地重新引入双平台运行。
- 测试数据无迁移和生产用户，因此回滚不涉及用户数据搬迁。浏览器本地状态通过 `fitness-local-backup-v1` 自助备份和恢复。
- 测试 Key 异常或疑似泄露时立即撤销，重新生成 `.env.test.local` 并重建未跟踪制品。

## 验证要求

- 原有领域、计算、版本、幂等、重算、过敏原和模型安全测试继续通过。
- 新增 IndexedDB 原子事务、schema 升级、容量、备份恢复、多标签冲突和删除测试。
- 新增 React 页面与 Playwright 完整流程测试。
- 普通自动化只使用固定 LLM/视觉桩；真实测试 LLM 只由显式预检命令调用。
- 最终扫描证明活动源码和构建脚本不再依赖 `wx.*`、CloudBase SDK、云函数入口或小程序构建。
- Git 秘密扫描证明真实测试 Key 未进入版本历史或已跟踪文件。

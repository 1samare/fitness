# 阶段七受控内测测试清单

本清单供测试人员在发布负责人明确通知“受控内测环境已就绪”后使用。当前仓库内存在本清单不代表云端已部署或可以开始测试；开始前必须取得本轮小程序版本、环境标签、数据集版本和测试窗口的私有通知。

测试只使用合成数据和专用微信测试身份。不得在缺陷单、聊天、截图文件名或共享表格中记录真实 OpenID、环境 ID、身体档案、过敏原、自由文本、照片/fileID、导出正文、联系信息、密钥或供应商响应。

## 1. 测试范围与停止条件

产品只面向健康成年人提供一般健身与膳食规划。自动个性化能量只支持同时满足以下条件的测试数据：

- 年龄 `18–45` 岁；
- BMI `18.5–<24.0`；
- 已明确完成最小健康排除项确认；
- 身高、体重、公式性别变量、非训练活动、目标和必要日期完整。

以下场景不得得到自动热量盈亏：疾病或治疗、孕哺期、未成年人、康复/伤病、进食障碍、医疗建议、极端目标、年龄/BMI 超出范围或未确认健康排除项。看到这些输入仍生成个性化能量时立即停止测试并按 P0 安全缺陷上报，不继续生成餐单。

所有能量、训练消耗、营养和克数必须显示“估算/仅供参考/不构成医疗建议”之一，不得出现“精准”“医学级”等表述。AI 辅助页面和内容必须有可见标识。

## 2. 开始前准备

测试负责人在私有证据系统记录以下内容，不粘贴真实值到本文件：

- 场景 ID、测试日期和测试负责人；
- 小程序受控内测版本；
- `planning-api`、`assistant-api`、`photo-cleanup` 版本标签；
- 审核数据集版本/checksum 标签；
- 设备系统与型号级别、网络类型；
- 身份标签 A/B；容量测试另用十个独立标签；
- 缺陷单编号和 pass/fail，不记录请求或响应正文。

至少准备：

1. 两个不同微信身份 A、B，各使用一台物理设备；
2. 一台 iOS 和一台 Android；
3. 两组处于支持范围内的合成档案；
4. 一组年龄/BMI/健康确认不满足的合成档案；
5. 已由发布负责人确认可用的审核食材中文名和足量库存克数；
6. 一张不含人物、位置、文字或其他个人信息的 JPEG/PNG 食材测试图；
7. 一个专用于图片删除失败/重试演练、允许永久删除的可丢弃账户。

不要使用真实健康数据、真实家庭照片、真实疾病信息或个人自由文本。

## 3. 页面入口

正常入口页为 `pages/planning-setup/index`。需要定位缺陷时可记录以下公开页面名，不记录带参数的真实链接：

| 页面 | 路径 | 正常入口 |
|---|---|---|
| 一周规划 | `pages/planning-setup/index` | 小程序首页 |
| 每日能量预览 | `pages/planning-preview/index` | 开发/专项验收入口 |
| 餐单与训练执行 | `pages/meal-execution/index` | “前往一周餐单与执行” |
| 受限计划助手 | `pages/assistant/index` | “打开受限计划助手” |
| 食材图片辅助 | `pages/ingredient-photo/index` | “拍照辅助识别食材” |
| 隐私说明 | `pages/privacy/index` | 各主页面“隐私说明” |
| 个人数据管理 | `pages/data-rights/index` | 各主页面“个人数据管理” |

若普通测试流程必须借助开发者控制台、隐藏路由或直接调用 API 才能继续，判为失败。

## 4. 双身份完整主流程

身份 A、B 分别完整执行以下步骤；除隔离验证外，不交换设备或账号：

1. 打开“一周规划”，录入支持范围内的合成身体档案、过敏原/忌口/偏好，并打开健康范围确认。
2. 选择维持、减脂或增肌目标，设置生效日/目标日和连续七天的规划周。
3. 安排至少两个审核训练会话并填写有效分钟，点击“保存并生成能量与营养目标”。
4. 核对成功信息、连续日期、估算/非医疗说明；刷新或重启后当前版本链仍一致。
5. 进入“餐单与训练执行”，逐行填写审核食材中文名和正克数，点击“校验名称”。未校验或歧义名称不能保存。
6. 选择今天或未来的餐单周，点击“保存库存并生成一周餐单”。核对恰好七天、每天三餐、食材克数和估算营养展示。
7. 对一个未来日打开“锁定餐单”，再在结构化规划页移动/取消训练或改变时长。
8. 返回餐单页，核对过去事实不变、未锁定未来日可产生新版本、锁定/手改日出现“确认锁定日差异”，且必须明确选择保留或覆盖。
9. 替换一餐菜品，确认只使用页面提供的审核候选；再记录今天或过去计划日的实际完成分钟数。
10. 若餐单重算暂时失败，训练事实仍显示已保存，并提供“重试餐单重算”或“刷新重算状态”，不得回滚已保存事实。
11. 打开受限助手完成一项支持命令，然后进入个人数据管理完成导出检查。

通过标准：过去记录不被新计划改写；所有活动版本引用一致；重复点击或网络重试不产生重复有效版本、重复事实、重复餐单或重复对话回执。

## 5. 锁定、手动修改与助手

助手只允许一次处理一条、最多 2000 字的以下三类请求：

- 移动未来训练日；
- 按页面可核对的精确中文菜名换菜；
- 将某餐份量调整为 `0.50–1.50` 倍，步长 `0.05`（或 `50%–150%`）。

使用本轮实际未来日期编写请求，不照抄过期示例。每条请求应显示“AI 辅助”，并先校验再调用确定性服务。测试以下拒绝项：过去日期、任意工具/URL/查询、用户身份字段、热量/MET/食材克数编造、绕过过敏原、未提供的菜名、超范围/非步长份量和不支持的自由任务。

版本冲突或 busy 时，页面应读取服务端 pending，并提供“重试原请求”“打开结构化训练计划”或“打开餐单并核对差异”之一；不得盲目重复调用模型。模型不可用时，结构化规划、餐单和确定性份量操作仍可使用。

## 6. 食材照片与手动降级

1. 从餐单页进入“拍照识别现有食材”，选择一张不含个人信息且小于 10 MiB 的 JPEG/PNG。
2. “上传并登记图片”和“识别候选食材”必须是两个明确步骤。
3. 识别结果只显示候选名称、食物状态和置信度；不得自动选择候选，不得猜测克数、热量或营养。
4. 明确选择候选并手工输入正整数克数后，才可点击“确认候选与克数并写入库存”。
5. 确认前返回餐单页，正式库存/营养/餐单不得变化；确认后只能追加版本。
6. 关闭网络或由发布负责人触发已批准的 Provider 故障控制，确认超时/重试/熔断后页面仍提供“手动录入食材”。
7. 使用手动录入完成核心流程；图片失败不能阻断餐单功能。

原图必须位于私有路径，确认后立即进入清理资格，未确认图不晚于 24 小时安排删除。测试人员只记录 cleanup pass/fail 和场景 ID，不记录图片、路径或 fileID。

## 7. 隔离与客户端边界

仅用普通小程序能力执行 A/B 双向矩阵：

- A 不能读取、导出、更正、删除、覆盖或枚举 B 的规划聚合；B 对 A 同样；
- A 不能读取、下载、登记或确认 B 的图片；B 对 A 同样；
- 两者都不能直接访问 `planning_user_states`、`planning_reviewed_datasets`；
- 两者都不能调用 `photo-cleanup`；
- 客户端提交伪造身份、内部版本、Provider、模型、工具或额外字段时失败关闭，且错误不透露另一账号是否存在。

只保存身份标签哈希和 pass/fail 矩阵。任何跨身份数据出现都按 P0 立即停止测试。

## 8. 导出、更正与永久删除

在“个人数据管理”执行：

1. 刷新摘要，核对档案/目标/训练/餐单/每日目标/照片/助手数量与本账号可见历史一致。
2. 点击“复制严格 JSON”或“生成临时 JSON 并分享”。JSON 必须可解析，数值可由公开输入复算，且包含策略/审核数据版本引用。
3. 导出不得包含用户身份主键、OpenID、私有 fileID、幂等键/指纹、内部摘要、内部 pending/回执、存储路径、供应商正文或密钥。
4. 点击“前往版本化更正”，修改合成档案/目标/训练；确认创建新版本且历史事实仍存在。
5. 对无图可丢弃账号验证一次成功删除。
6. 对专用图片账号按发布负责人编排验证一次存储删除失败：账户进入 pending，正常业务 API 被阻断但业务数据仍保留；权限恢复后必须使用同一删除命令重试。
7. 永久删除前必须完整输入两段确认文本：`删除我的账户` 和 `DELETE_MY_ACCOUNT`。这是不可撤销操作，不在非专用账号上测试。
8. 删除成功后服务端文档/对象不存在、本地恢复状态清除；重新打开可创建干净新账户，旧幂等命令不能作用于新账户。

导出正文和删除截图只进入私有证据，并按测试证据保留策略删除。

## 9. 固定失败与恢复预期

测试人员以页面文案为准，缺陷记录可附下列稳定错误码，但不得附原始响应正文：

| 错误码/状态 | 期望行为 |
|---|---|
| `unsupported_for_personalized_energy` | 明确“不生成个性化能量目标”，不切换公式 |
| `nutrition_constraints_infeasible` | 显示结构化冲突和可操作提示，不放宽过敏原/健康边界 |
| `provider_unavailable` | 营养/图片/助手使用固定降级；既有事实和计划不丢失 |
| `version_conflict` / `conversation_version_conflict` | 提示刷新并读取服务端当前状态，不无限自动重试 |
| `account_deletion_pending` | 只允许同一删除请求继续，其他规划/助手操作被阻断 |
| `personal_data_snapshot_conflict` | 自动刷新摘要后由用户重新发起导出 |
| `account_capacity_exceeded` / `admin_recovery_required` | 不截断历史，提示联系隐私支持 |
| `unauthenticated` | 不显示任何账号数据，提示需要可信微信身份 |

出现堆栈、数据库/集合名、供应商正文、fileID、签名 URL、OpenID、密钥或完整内部对象时按安全缺陷处理。

## 10. 隐私与公开文案

从规划、餐单、助手、图片页面分别打开“隐私说明”和“个人数据管理”，确认：

- 发布通道为受控内测，运营主体、隐私联系和说明版本为本轮真实公开值；
- 处理目的、最小化收集、照片 24 小时内清理、访问/导出/更正/删除权利可见；
- 用户提供、AI 辅助、确定性估算三类内容来源清晰；
- 健康成年人和非医疗限制可见；
- 隐私联系入口可以复制或打开，但缺陷单不记录其真实值。

文案为空、仍为 local/dev/tourist 值、AI 标识缺失或权利入口不可达时，本轮发布失败。

## 11. 设备、网络与幂等

至少在一台 iOS 和一台 Android 完成：首次安装、后台/恢复、页面重启、重复点击、响应丢失后的同请求重试、Wi-Fi 切移动网络、Provider 超时、图片上传重试、导出复制/分享和删除后重启。

网络恢复后必须读取权威服务端状态；不得重复生成版本或要求测试人员手工清除数据库。若只能通过清缓存恢复，判为失败。

## 12. 证据与缺陷提交

每个场景只记录：场景 ID、版本标签、设备系统/型号级别、匿名身份标签、开始/结束时间、终态类型、耗时和 pass/fail。截图先遮盖身体档案、自由文本、联系值和所有 ID；不得上传导出 JSON、原图、日志正文或供应商响应。

缺陷标题建议：`[P0-P3][场景ID][页面] 简短现象`。正文写复现步骤、预期、实际、匿名版本标签和证据引用。隐私/安全、错误身份数据、过敏原放宽、医疗越界、历史改写或删除失效均立即停止相关测试并通知发布/隐私负责人。

## 13. 最终签署

以下项目必须全部为 pass 才能签署测试完成：

- [ ] A/B 完整主流程与双向隔离
- [ ] 审核营养成功和不存在/过期/断链失败关闭
- [ ] 锁定/手改确认与训练完成联动
- [ ] Vision/Assistant 超时、重试、熔断、恢复与手动降级
- [ ] 图片及时清理与敏感日志零命中
- [ ] 导出、更正、无图删除、图片删除失败/重试、账户重建
- [ ] 10 个身份 × 30 个操作和预算/配额通过
- [ ] 两集合恢复到新名称与前向回滚通过
- [ ] iOS/Android、网络切换和重复操作通过
- [ ] 隐私、非医疗、AI 标识、供应商授权和审批材料通过

任何一项缺少真实证据时只可写“本地代码就绪/测试准备完成”，不得写“受控内测已发布”或“阶段七已完成”。

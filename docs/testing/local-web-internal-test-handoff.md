# 本地优先 Web 内测交接

## 交付状态

- 状态：虚拟数据 Web 内测已交付，非生产。
- 人数上限：最多 5 名已授权内部测试人员。
- 数据边界：只允许合成测试数据，不得录入真实健康数据、真实照片或可识别个人的信息。
- 部署边界：静态 Web 测试构建；无服务器、无远程数据库、无云端文件存储。

## 固定数据与版本边界

- 本地数据 schema：`fitness-local-db-v1`。
- 备份 schema：`fitness-local-backup-v1`。
- 测试规划数据：`local-test-planning-dataset-v1`，`datasetId=local-test-planning-cn-v1`。
- 营养 fixture：`fixture-balanced-meal-planning-2026-08-10`。
- 能量策略：`calculation-policy-v2`；营养策略：`nutrition-policy-v1`。
- 恢复时必须匹配数据集身份与版本，并明确勾选覆盖；失败时保持旧数据原子可用。

## 测试构建与密钥撤销

1. 在私有 `.env.test.local` 中设置 `VITE_TEST_LLM_BASE_URL`、`VITE_TEST_LLM_API_KEY`、`VITE_TEST_LLM_MODEL`。
2. 先运行 `pnpm web:test:preflight`，仅验证可用性，不记录密钥、请求正文或响应正文。
3. 运行 `pnpm build:web:test`。普通 `pnpm build:web` 必须保持零密钥且禁用 AI 路径。
4. 仅向最多 5 名授权人员提供短期测试构建；不得公开托管或转发。
5. 测试结束立即在供应商侧撤销测试 Key，删除 `.env.test.local`、测试构建和浏览器站点数据。

## 验收流程

1. 确认“内部虚拟测试、估算值、AI 辅助、非医疗建议”边界。
2. 完成身体档案、目标和一周训练计划，检查七日营养目标。
3. 保存测试库存，生成七日餐单，记录训练完成度并确认后续日期重算。
4. 使用无个人信息的测试图片，确认最多五个候选；必须手动选择名称并输入正整数克数。
5. 验证模型失败时仍可手动录入，两个标签页的旧版本写入被拒绝。
6. 下载完整备份，确认不含 API Key 与图片 data URL；执行删除、覆盖恢复和最终删除。

## 明确不在范围内

- 真实用户、真实健康数据、真实食材照片或医疗用途。
- 生产营养数据授权、生产模型合同、备案、公开发布、SLA、遥测与远程恢复。
- 多设备同步、多人协作、服务端身份、服务端数据库、对象存储和离线安装包。
- 超过 5 人的测试、公开 URL、应用商店或小程序发布。
